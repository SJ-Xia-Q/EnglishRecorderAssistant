# ADR-0001：采用 Manifest V3 页面悬浮助手

## 状态

已接受

## 背景

独立 HTML 页面要求用户启动本地服务、切换窗口并手动同步剧本，不适合向其他录制人员分发。录制平台页面可能很长，剧本、录音按钮和录音时长无法同时出现在一个视口内。插件必须辅助计时，同时避免接管麦克风或破坏原平台录音流程。

## 决策

实现一个仅匹配语录入口 `https://bytedance.aiforce.cloud/app/*` 与登录后任务域名 `https://bytedance.feishuapp.com/app/*` 的 Chrome/Edge Manifest V3 扩展。内容脚本自动读取剧本，在 Shadow DOM 中渲染可拖动的悬浮计时面板，并通过一个专用属性固定原平台真实录音控件。用户可隐藏助手，扩展工具栏图标通过轻量后台消息恢复当前标签页中的同一会话。

红词轮只有一条路径：用户在读完红词时点击按钮或按空格，插件计时 5 秒，归零后自动执行本轮标注的静音。由于已确认红词后至少有 15 个词，不实现文本不足分析和提前静音。

## 后果

### 正面

- 用户始终在原平台完成录音，无需切换页面。
- 不申请麦克风权限，不产生第二份录音，也不会与平台争用设备。
- 原生录音控件保留真实事件、状态和权限行为。
- 状态机分支少，提示更短，误触面更小。

### 负面

- 平台 DOM 结构变化可能使剧本或录音控件识别失效。
- 内测用户需要开启开发者模式并加载解压目录。
- 真实平台验收需要有效登录状态，无法完全由离线夹具替代。

### 中性

- 第一版针对 Chrome/Edge，不承诺 Firefox 或 Safari 兼容。
- 插件只辅助操作，不改变平台提交与质检规则。

## 备选方案

**独立 HTML 录音页**：分发与使用步骤较多，且会与原平台形成双界面，拒绝。

**插件自行录音并导出音频**：需要麦克风权限和格式适配，可能与平台录音冲突，拒绝。

**复制原平台录音按钮到插件面板**：复制状态容易与真实控件失步，程序化点击也增加兼容风险，拒绝。

**Chrome Side Panel**：能与页面并排显示，但占用横向空间且仍需用户打开；固定悬浮层更符合“滚动时始终可见”，第一版不采用。
