# 录音区随动与 F8 快捷键设计

## 问题与取舍

当前原平台录音区被独立固定在视口底部中央，宽度最高 720px。它虽然始终可见，但会覆盖平台底部的提交按钮，也不会跟随节奏助手移动。直接把平台录音 DOM 移进助手的 Shadow DOM，视觉上最像一个组件，却可能破坏平台框架的父子关系、事件委托和录音状态，因此不采用。

采用“视觉绑定、不改变 DOM 归属”的侧挂方案：节奏助手仍是拖动主体，原平台录音节点仍留在原父节点中，只通过命名空间属性和 CSS 变量固定到助手旁边。助手每次布局、拖动、折叠或窗口缩放后，把自己的视口矩形交给录音区布局函数。录音区优先放在助手左侧，空间不足时尝试右侧，再在窄屏上放到上方或下方。所有位置都限制在视口内。

录音区默认使用紧凑尺寸并限制最大高度，内容过多时只在录音卡片内部滚动；助手提供“展开录音区 / 缩小录音区”按钮，展开状态保存在浏览器本地。关闭助手时移除录音区的悬浮属性，使它立即回到平台原位置；点击扩展图标恢复助手时重新侧挂。这样关闭的是整个辅助悬浮组，不会把平台原生控件隐藏。

## 键盘操作

保留键盘效率，但完全删除空格快捷键。空格具有页面滚动、按钮激活和文本输入等原生含义，继续抢占会产生不可预测冲突；仅靠焦点白名单又会造成用户描述的“经常失效”。

新的唯一快捷键为 `F8`。监听器工作在页面捕获阶段，不检查焦点目标，因此焦点位于平台按钮、输入框或剧本区时都能触发。`F8` 不输入字符，也不是 Chrome 页面滚动键。只在节奏状态为“正在朗读”时接受一次非重复按键；倒计时中、错误态和完成态一律忽略。触发时阻止该次事件继续交给平台，避免同一按键被双方处理。鼠标主按钮始终保留，界面中的引导、按钮键帽、页脚和 README 全部改为 `F8`。

## 验收原则

- 默认录音区不再固定在视口底边，不覆盖夹具中的提交操作区。
- 拖动助手时，录音区以相同位移跟随；紧凑与展开两种尺寸均留在视口内。
- 360×420、512×384 等窄小视口下允许自动改为上下排列，但不得跑出视口。
- 关闭助手后录音节点回归平台布局；工具栏恢复后重新随动。
- 输入框和平台录音按钮拥有焦点时，`F8` 仍触发助手且不点击平台按钮；空格不再改变助手状态。
- 不克隆录音控件、不代理麦克风操作、不触发录音、上传或提交。
